# 漂移评测协议

这份文档是整个工作的**方法论部分**，论文的「实验设置」一节基本可以照此撰写。
它比模型本身更重要：审稿人最常质疑的就是「你这个分布漂移是不是人为造出来的」。

## 1. 为什么需要专门的漂移协议

已有的时序异常检测基准（含 TSB-AD）默认训练段与测试段同分布。
但真实部署中这条不成立。我们关心的问题是：

> 在同分布下表现良好的方法，在什么条件下会失效？失效的原因是什么？

回答这个问题需要**可控、可复现、可归因**的漂移划分，而不是拿现实数据里
无法解释的分布差异做「玄学」对比。

## 2. 三条硬性约定

### 2.1 只动一侧

每个协议只修改训练段或只修改测试段，绝不同时修改，否则无法归因。
本仓库四个协议的修改位置：

| 协议 | 修改训练段 | 修改测试段 | 标签 |
| --- | --- | --- | --- |
| `temporal` | 是（减小并偏移） | 否 | 不变 |
| `channel` | 否 | 是（置换） | 不变 |
| `channel_mask` | 是（屏蔽一部分） | 是（屏蔽另一部分） | 不变 |
| `amplitude` | 否 | 是（尺度+偏移） | 不变 |

`channel_mask` 是唯一的例外，但它的对称性正是设计意图：
两边屏蔽相同比例，只有「屏蔽的是哪些通道」不同。

### 2.2 先归一化，后漂移

管线顺序固定为：

```
加载 -> 用训练段统计量归一化 -> 施加漂移 -> 训练/评测
```

原因是：z-score 归一化会**吸收掉全局尺度漂移**。如果先漂移再归一化，
一个全局 `x -> 1.5x` 会被标准差归一化完全抹掉，实验就白做了。
我们的 `amplitude` 协议因此使用**逐通道**的相对尺度，保证漂移不可被吸收。

这条约定写在 `src/datasets/__init__.py:build_pipeline` 里，代码层面强制执行。

### 2.3 测试段标签与长度不变

所有协议都保持测试段的时序长度、通道数、异常标签完全不变。
这样不同协议下的指标是同一批异常区间上的数值，可以直接横向比较。

## 3. 四个协议分别诊断什么

- **`temporal`**：诊断「工况切换」。训练段被压到原长度的 1/5 且明显偏离测试分布。
  预期现象：所有方法掉点，掉得最多的是容量最大、最容易过拟合训练分布的方法。
- **`channel`**：诊断「通道关系建模」的双刃剑。由于**不改变任何单通道的边缘分布**，
  逐点方法（`zscore`、`iforest`）理论上几乎不受影响，而显式建模通道依赖的方法
  会受到冲击。如果你的通道图方法在 `channel` 下崩得比 `iforest` 还狠，
  说明通道建模在当前形式下是负资产——这是必须如实报告的负结果，
  也是「为什么需要稀疏化/不变性约束」的直接动机。
- **`channel_mask`**：诊断「传感器增删」。更接近工程现实，也更容易做出正收益。
- **`amplitude`**：诊断「标定漂移」。专门打击依赖固定阈值与固定边缘分布的方法，
  `adaptive_zscore` 在这里通常表现很好——这正是「在线重估统计量」的价值所在。

## 4. 必须报告的混淆因素（消融清单）

漂移实验天然带着几个混淆因素，不控制就会被审稿人抓住：

1. **数据量**。`temporal` 把训练段缩到 1/5，性能下降可能只是数据变少。
   → 必须补一组「在 `none` 下只用 1/5 训练数据」的对照，见
   `configs/model/*.yaml` 里 `data.limit_length` 的用法（待实现项，见 §6）。

2. **`adaptive_zscore` 基线**。它在测试流上重算均值方差。
   如果你的方法打不过它，说明收益只是「做了在线归一化」。
   → 论文里必须单独列出这一行。

3. **TTA 的两级拆解**。我们的 `tta` 分 `recenter`（重估统计量）与
   `finetune`（自监督微调）。必须给出三个数字：
   `tta=false`、`tta=true, tta_finetune=false`、`tta=true, tta_finetune=true`。
   否则无法说明增益来自哪一级。

4. **随机性**。每个配置至少 3 个种子，报告 mean ± std，
   并用 `src/eval/stats.py` 的配对 Wilcoxon 检验说明提升是否显著。

## 5. 指标口径

- 主指标 `VUS-PR` 与 `AUC-PR`。异常占比通常 <5%，`AUC-ROC` 会显著高估。
- `point_adjust_f1` **只能作为对照列**，并在论文里写明它偏乐观的原因
  （区间内检出一个点即算整个区间检出）。
- `src/eval/metrics.py` 里的 `vus_pr` 是开发期近似实现，
  **论文数字必须来自 TSB-AD 官方评测器**（`src/eval/official.py`）。
